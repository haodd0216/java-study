## Positioning

日期与时间 API 位于 Java 知识树的 **常用核心 API → 日期与时间 API** 分支，它解决的是“如何正确表达日期、时间、时间间隔和时间计算”的问题。

## Analogy

可以把日期时间 API 想成几种不同的尺子。量身高用厘米尺，量体重用体重秤，量温度用温度计。它们都和“测量”有关，但不能混用。

Java 日期时间里也是这样：

- `LocalDate` 像日历，只关心年月日，例如 `2026-09-02`。
- `LocalTime` 像钟表，只关心时分秒，例如 `14:30:00`。
- `LocalDateTime` 是日历加钟表，例如 `2026-09-02 14:30:00`。
- `Period` 表示日期层面的间隔，例如 1 年、2 个月、3 天。
- `Duration` 表示精确时间层面的间隔，例如 3 小时、20 分钟、10 秒。

你在枚举练习里已经发现了一个很好的问题：会员卡到期时间不能只用 `int startYear` 表达。比如月卡、季卡、按天体验卡，都不能靠“年份 + years”准确描述。这就是应该引入 `LocalDate` 和 `Period` 的地方。

## Core Mechanism

Java 8 之后推荐使用 `java.time` 包下的新日期时间 API，而不是老的 `Date`、`Calendar`。核心原因是新 API 更清晰、更安全，也更适合做业务计算。

最常用的几个类型是：

1. `LocalDate`：只表示日期，不带具体时间，也不带时区。
2. `LocalTime`：只表示一天中的时间，不带日期，也不带时区。
3. `LocalDateTime`：表示日期 + 时间，但仍然不带时区。
4. `Period`：表示“几年几月几日”这种日期间隔。
5. `Duration`：表示“几小时几分钟几秒”这种时间间隔。
6. `DateTimeFormatter`：负责日期时间和字符串之间的格式化/解析。

先看 `LocalDate`。如果你的业务只关心会员卡从哪一天开始、哪一天到期，就应该用它：

```java
LocalDate startDate = LocalDate.of(2026, 9, 2);
LocalDate expireDate = startDate.plusYears(1);
```

这比 `int startYear = 2026` 更准确，因为它保留了月份和日期。`2026-09-02` 加一年得到 `2027-09-02`，而不是一个粗糙的 `2027`。

再看 `Period`。如果卡类型有“1 年”、“2 年”、“1 个月”，用 `Period` 会比自己维护 `years` 字段更灵活：

```java
Period oneMonth = Period.ofMonths(1);
Period oneYear = Period.ofYears(1);
```

这样月卡就不会逼你把模型塞进 `years` 里。

`Duration` 和 `Period` 的区别很重要：

- `Period.ofDays(1)` 是日历意义上的 1 天。
- `Duration.ofHours(24)` 是精确的 24 小时。

大多数会员卡、合同、生日、账单周期，通常用 `LocalDate + Period`。倒计时、任务超时、接口耗时、缓存过期，通常用 `Instant/Duration` 或 `LocalDateTime/Duration`。

还要注意：`LocalDate`、`LocalDateTime` 都是不可变对象。调用 `plusDays()`、`plusMonths()`、`plusYears()` 不会修改原对象，而是返回一个新对象：

```java
LocalDate today = LocalDate.of(2026, 9, 2);
LocalDate tomorrow = today.plusDays(1);
```

执行后，`today` 仍然是 `2026-09-02`，`tomorrow` 是 `2026-09-03`。

字符串和日期互转时，使用 `DateTimeFormatter`：

```java
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd");
LocalDate date = LocalDate.parse("2026-09-02", formatter);
String text = date.format(formatter);
```

## Code Example

```java
import java.time.LocalDate;
import java.time.Period;
import java.time.format.DateTimeFormatter;

enum CardDuration {
    ONE_MONTH("月卡", Period.ofMonths(1)),
    ONE_YEAR("一年卡", Period.ofYears(1)),
    THREE_YEARS("三年卡", Period.ofYears(3)),
    LIFETIME("终身卡", null);

    private final String text;
    private final Period period;

    CardDuration(String text, Period period) {
        this.text = text;
        this.period = period;
    }

    boolean isLifetime() {
        return this == LIFETIME;
    }

    LocalDate expireDateFrom(LocalDate startDate) {
        if (isLifetime()) {
            return LocalDate.of(9999, 12, 31);
        }
        return startDate.plus(period);
    }

    String getText() {
        return text;
    }
}

public class DateTimeDemo {
    public static void main(String[] args) {
        DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd");

        LocalDate startDate = LocalDate.parse("2026-09-02", formatter);
        LocalDate oneMonthExpireDate = CardDuration.ONE_MONTH.expireDateFrom(startDate);
        LocalDate threeYearsExpireDate = CardDuration.THREE_YEARS.expireDateFrom(startDate);

        System.out.println(CardDuration.ONE_MONTH.getText() + "到期日: " + oneMonthExpireDate.format(formatter));
        System.out.println(CardDuration.THREE_YEARS.getText() + "到期日: " + threeYearsExpireDate.format(formatter));
    }
}
```

这段代码把“会员卡到期计算”从 `int startYear` 升级成了 `LocalDate startDate`。月卡可以用 `Period.ofMonths(1)`，一年卡可以用 `Period.ofYears(1)`，三年卡可以用 `Period.ofYears(3)`。这样模型就能表达真实业务里的年月日，而不是只表达年份。

## Common Misconceptions

第一个常见误解：所有时间都用 `LocalDateTime`。其实如果业务只关心日期，就用 `LocalDate`。多放一个时间部分，反而会制造无意义的问题，例如到底是当天 `00:00` 到期，还是 `23:59:59` 到期。

第二个常见误解：`Period` 和 `Duration` 差不多。它们不一样。`Period` 是日历单位，适合年、月、日；`Duration` 是精确秒数/纳秒，适合小时、分钟、秒。会员卡有效期一般更适合 `Period`。

第三个常见误解：`plusDays()` 会修改原日期对象。不会。`java.time` 里的核心类型大多是不可变对象，调用加减方法会返回新对象。

第四个常见误解：日期格式化可以自己拼字符串。简单场景看起来可以，但一旦有补零、解析、格式一致性，就应该交给 `DateTimeFormatter`。

第五个常见误解：`LocalDateTime` 就是一个完整时间点。不是。`LocalDateTime` 没有时区，不能唯一表示全球时间线上的某一瞬间。如果以后学到日志时间、服务器时间、跨时区业务，会接触 `Instant`、`ZoneId`、`ZonedDateTime`。

## Quick Summary

- Java 8 之后优先使用 `java.time` 包处理日期时间。
- 只关心年月日用 `LocalDate`，只关心时分秒用 `LocalTime`，日期加时间用 `LocalDateTime`。
- 会员卡、账单周期这类按年月日计算的业务，通常用 `LocalDate + Period`。
- `Period` 表示日期间隔，`Duration` 表示精确时间间隔。
- `java.time` 类型通常不可变，日期加减会返回新对象。
- 字符串和日期互转用 `DateTimeFormatter`。
