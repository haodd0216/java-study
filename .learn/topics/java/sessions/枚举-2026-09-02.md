## Positioning

枚举位于 Java 知识树的 **常用核心 API → 枚举** 分支，它通常用来表示“一组固定、有限、可命名的取值”。

## Analogy

可以把枚举想成“官方菜单”。比如会员卡类型只有三种：一年卡、三年卡、终身卡。如果用普通字符串，任何人都可以写出 `"一年卡"`、`" 一年卡"`、`"1年卡"`、`"黄金卡"`，程序很难保证输入一定合法。枚举就像把菜单贴在柜台上：只能从菜单上的选项里点，不能随便写一个不存在的菜名。

## Core Mechanism

枚举的核心作用是：把一组固定值从“容易写错的字符串/数字”变成“编译器能检查的类型”。

在你当前的会员练习里，`Member` 有一个字段：

```java
String cardType;
```

这能工作，但它有几个问题：

1. 字符串容易写错，例如 `"三年卡"` 和 `"三 年卡"` 对程序来说是两个不同值。
2. 字符串没有范围限制，`"宇宙卡"` 也能被传进去。
3. 比较字符串要用 `equals()`，不能用 `==`，这和你刚学过的包装类比较陷阱很像。
4. 如果以后卡类型要带价格、年限、展示文本，用字符串会越来越散。

枚举可以把这些固定选项定义成一个专门的类型：

```java
enum CardType {
    ONE_YEAR,
    THREE_YEARS,
    LIFETIME
}
```

这样 `Member` 就可以写成：

```java
class Member {
    String name;
    String phone;
    CardType cardType;
}
```

这时 `cardType` 不能随便传字符串了，只能是 `CardType.ONE_YEAR`、`CardType.THREE_YEARS`、`CardType.LIFETIME` 之一。错误会尽早暴露在编译阶段，而不是运行很久之后才发现数据乱了。

Java 枚举不只是“一堆常量”。每个枚举值本质上都是这个枚举类的一个固定对象，而且是单例对象。因此枚举值可以安全地用 `==` 比较：

```java
if (cardType == CardType.THREE_YEARS) {
    System.out.println("这是三年卡");
}
```

这和 `String`、`Integer` 不同。字符串内容比较一般用 `equals()`；包装类值比较也建议用 `equals()`；但枚举比较通常直接用 `==`，因为每个枚举常量只有一个固定实例。

枚举还可以带字段、构造方法和方法。比如我们希望每种卡都有中文名称和有效年限：

```java
enum CardType {
    ONE_YEAR("一年卡", 1),
    THREE_YEARS("三年卡", 3),
    LIFETIME("终身卡", -1);

    private final String text;
    private final int years;

    CardType(String text, int years) {
        this.text = text;
        this.years = years;
    }

    public String getText() {
        return text;
    }

    public int getYears() {
        return years;
    }
}
```

注意枚举构造方法不能用 `public`。枚举值必须在枚举内部提前列出来，外部不能随便 `new CardType()`。

## Code Example

```java
enum CardType {
    ONE_YEAR("一年卡", 1),
    THREE_YEARS("三年卡", 3),
    LIFETIME("终身卡", -1);

    private final String text;
    private final int years;

    CardType(String text, int years) {
        this.text = text;
        this.years = years;
    }

    public String getText() {
        return text;
    }

    public int getYears() {
        return years;
    }
}

class Member {
    String name;
    String phone;
    CardType cardType;

    Member(String name, String phone, CardType cardType) {
        this.name = name;
        this.phone = phone;
        this.cardType = cardType;
    }

    @Override
    public String toString() {
        return name + "[" + phone + "] - " + cardType.getText();
    }
}

public class EnumDemo {
    public static void main(String[] args) {
        Member m = new Member("张三", "13800138000", CardType.THREE_YEARS);

        System.out.println(m);

        if (m.cardType == CardType.THREE_YEARS) {
            System.out.println("三年卡会员");
        }

        System.out.println("有效年限：" + m.cardType.getYears());
    }
}
```

这段代码里，`CardType` 定义了三种合法会员卡。`Member` 不再保存普通字符串，而是保存 `CardType`。这样会员的卡类型既有固定范围，又能携带中文展示文本和年限信息。

## Common Misconceptions

第一个常见误解：枚举只是替代字符串的语法糖。更准确地说，枚举是在创建一个有固定实例的类型。它不仅能防止拼写错误，还能承载字段、构造方法和行为。

第二个常见误解：枚举比较也必须用 `equals()`。枚举可以用 `equals()`，但实际开发中更常用 `==`，因为枚举常量是唯一实例，而且 `==` 遇到左边为 `null` 时也不会像调用方法那样直接空指针。比如 `cardType == CardType.ONE_YEAR` 是常见写法。

第三个常见误解：枚举值名字应该直接写中文。Java 里枚举常量通常用大写英文标识符，例如 `ONE_YEAR`。展示给用户看的中文文本放在字段里，例如 `"一年卡"`。

第四个常见误解：所有固定文本都要做成枚举。枚举适合“业务上有限且稳定”的集合，比如订单状态、会员卡类型、性别选项、设备状态。不适合频繁变化、需要用户自由输入、或者来自数据库动态配置的数据。

## Socratic Check

想一想：在你的 `Member` 类里，`cardType` 现在是 `String`。如果有人传入 `" 三年卡"` 或 `"三年卡 "`，你需要靠 `trim()` 修正；如果有人传入 `"五年卡"`，现在的构造方法也不会拦住。换成 `CardType.THREE_YEARS` 后，哪一类错误会更早被发现？

另一个问题：你刚学过 `Integer` 不能随便用 `==` 比较值，因为有缓存陷阱。那么为什么枚举反而常用 `==`？关键原因是枚举常量不是临时包装出来的值，而是枚举类中预先创建好的固定对象。

## Socratic Check Feedback

你的回答：

1. 使用 `CardType.THREE_YEARS` 在编译阶段就会发现错误。
2. 枚举值在定义时就已经确定。

反馈：两个判断都正确。第一点说明你已经理解了枚举相对字符串的核心优势：非法取值不再只是运行时数据问题，而会尽量提前变成编译期类型问题。第二点也抓住了枚举能用 `==` 比较的原因：枚举常量是在枚举类中预先声明好的固定实例，不是每次临时创建的新对象。

## Quick Summary

- 枚举用于表示一组固定、有限、可命名的合法取值。
- 枚举比字符串更安全，因为编译器能帮你检查非法值。
- 枚举常量是固定实例，实际开发中通常用 `==` 比较。
- 枚举可以有字段、构造方法和方法，不只是简单常量。
- 用户展示文本建议放在枚举字段里，不建议直接用中文枚举常量名。
